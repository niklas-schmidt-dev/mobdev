# Mobdev development

- Three parts: `macos/` (SwiftUI app, no JS/TS), `relay/` (self-hosted Go relay), `cloud/` (mobdev.sh on Cloudflare: TanStack Start website and dashboard, relay worker with Durable Objects, D1, WorkOS).
- Validation: `macos`: `swift test`, `scripts/build-app.sh`. `relay`: `go vet ./... && go test -race ./...`. `cloud`: `bun run typecheck && bun run test && bun run build`. Verify changed UI or device behavior in the running app, not only compilation.
- The app must look and behave like a first-party macOS 26 app (Liquid Glass, standard controls, `NavigationSplitView`, inspector, Settings scene). Keep `MobdevCore` free of UI; the `Mobdev` target stays thin.
- `PhoneTools` is the single tool contract for MCP, REST and the relays. Update `macos/README.md` and `cloud/src/routes/docs.tsx` when tools change.
- The website is in English and German (`/de/…`). Mark new or changed text with General Translation's `<T>`, `useGT()` or `msg()`, run `bun run translations` in `cloud/`, and translate the new entries in `cloud/src/_gt/de.json` by hand ("du", see `cloud/README.md`); never use GT's translation API. Page titles and descriptions are in `cloud/src/lib/meta.ts`.
- The relay protocol (WebSocket at `/v1/host/connect`, JSON `request`/`response` frames, the relay's `cancel` frame when it stops waiting for a request (timeout; the Go relay also when the agent hangs up), the Mac's `devices` frame listing its iPhones (validated in `relay/relay.go` and `cloud/shared/devices.ts`, listed at `/v1/relay/devices` and, hosted only, `/v1/account/devices`), `ping`/`pong`, close 4000 replaced / 4001 revoked), live view's `/v1/live` socket and `live_*` frames (`LiveStreams.swift`, `relay/live.go`, `cloud/shared/live.ts`) and the client-key derivation are shared by `RelayClient.swift`, `relay/relay.go` and `cloud/relay/src`. All three test the same key vector; change them together.
- A commit that changes something Mac app users notice gets a `Release-Note: New|Improved|Fixed: <one plain sentence>` line in its message. `macos/scripts/release-notes.py` turns these into the update window's "What's New" and the GitHub release notes; commits without one are not listed.
- Local builds are "Mobdev Dev" (`scripts/build-app.sh`, bundle ID `dev.mobdev.mac.dev`, port 4687, `mobdev-dev://`). Niklas runs the released app from `/Applications/Mobdev.app`: never build or launch the release variant locally, and never quit, replace or reconfigure the installed app or its data.
- Secrets: API token, relay secret and settings are 0600 files in `~/Library/Application Support/dev.mobdev.mac` (the dev app uses `dev.mobdev.mac.dev`; `MOBDEV_HOME` overrides). `Mobdev mcp` reaches the app over `mobdev.sock` there, never the TCP port, so no other user can pose as the app. Access tokens are stored hashed in D1. Never commit `.dev.vars`, tokens or device screenshots.
- Hosted relay plans (Free, Pro) live in `cloud/shared/plans.ts`; `cloud/autumn.config.ts` pushes them to Autumn, which holds balances and bills through Stripe. Change numbers there only, and keep the relay's fixed limits (`cloud/relay/src/protocol.ts`, `ratelimits` in `cloud/relay/wrangler.jsonc`) in step with the docs. Tests use `cloud/test/fake-autumn.ts`; the Autumn sandbox is for manual checks.
- Build scripts sign ad hoc. Do not sign with real identities, notarize, deploy, push plans to Autumn production (`atmn push --prod`) or change WorkOS/Cloudflare/Autumn/Stripe production settings without explicit authorization. The WorkOS sandbox for development is "Mobdev dev" in "Niklas Schmidt's Project"; never touch other projects' environments.
- Never send input (taps, typing) to a real iPhone during verification without asking. Automated tests use `FakePhone` and fake Macs.
- Dev servers run through Portless with `dev-scope` names (`web.$DEV_NAMESPACE`, `relay.$DEV_NAMESPACE`); stop them when done.
